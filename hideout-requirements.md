Shipping Rules
What counts as a shipped project?
Any projects ideas you have! but things these are not allowed:
If your project is for school;
If your project was submitted to another Competition (ie. Game Jam, VRC, FTC)
If your project has a sandbox paywall integration - You need to publish with Production payments flow! 
If your project is closed source;
If your project is a 1:1 replica of a tutorial - You need to remix/fork it, and add your own features!
Horizontal Rule
How do I ship my project?
It's super easy! Just remember that there are 3 main things your project has to have:
Easily testable demo
What is "easily testable demo"? 
Your demo must have no prerequisites to test it if possible to count as easily testable. Please refer to the Demo section for more details
An open source repository
What is "Open sourced repository"?
Repository that is public, and accessible by anyone. More information regarding your repository requirements - you can find it below, in the section "Repository"!
A robust README
What is "A robust README"?
A clear information of your project. More information regarding your README requirements - you can find it below, in the section "README"!
Make Sure to track your time using both #kairos and Hackatime.
both complements each other and you just need to leave them running for any questions ask in #hideout-help 
Horizontal Rule
Demo
This really depends on what kind of project it is! Different projects get shipped differently, but you want other people to be able to experience your project as easily as possible. Here are some examples of what is and isn’t okay. For all project types, we must have a downloadable or other easily usable demo, we cannot build the project ourselves locally.
Static web apps/websites:
You can deploy it on GitHub Pages, Vercel, Netlify, etc.., so everyone can see your live website;
You can't use a tunnel link (like ngrok or Cloudflare Tunnels), because it needs to be hosted somewhere permanently;
You can't put your GitHub Repo as your Demo URL with instructions how to host it locally - it's not easily demoble! 
Full-stack web apps (with databases/backend)
Deploy it to the web! Of course, depends on how much resources your backends needs, but you can always buy cloud hosting credits from the shop to buy a premium plans, if free-tiers aren't enough;
If there's an authentication system, everyone should be able to create an account, including third-party OAuths;
Hosting on Railway or Render free tiers aren't accepted because there's no guarantee they'll host it indefinitely, and they can have very slow cold starts.
You can also host your project on #nest! 
Games:
You have to build your game source, and publish play-ready files! Game should be hosted/put in the GitHub Releases or on platforms like itch.io;
You can't leave your game unbuilt with only source code, that makes everyone to build the project locally!
Game mods/plugins:
Publish your mod(s)/plugin(s) on platforms like - Modrinth, Curseforge or SpigotMC;
You can't publish your mod(s)/plugin(s) on GitHub Releases;
You can't leave your mod(s)/plugin(s) unbuilt with only source code, that makes everyone to build the project locally!
Bots (Discord, Slack, etc...):
It has to be hosted! Provide a link to a testing channel or server as a demo link, and ensure each command is properly documented in your README;
You can't leave your bot unhosted with only source code, that makes everyone to build the project locally!
Browser extensions:
You can publish it on the relevant stores like - Firefox Addons or Chrome web store (not mandatory);
If you're not publishing on the stores (above point) - Upload a one-click-install extension file (.crx) to GitHub Releases;
You can't leave your browser extension unbuilt (without .crx file) with only source code, that makes everyone to build the project locally!
Userscripts:
You have to publish it to Tampermonkey or Greasyfork;
Don't leave/use as your demo a .txt file, or link to GitHub Releases!
Command line tools
Publish it on the package index for your language like - PyPi for Python, NPM for JavaScript/TypeScript, crates.io for Rust, etc...;
You can't leave your CLI unpublished as that requires everyone to install dependencies and run specific files!
Libraries
You should publish your library to a library manager like - PyPi for Python or Cargo for Rust;
You should not require the user to manually add your libraries source files into their project without a library manager; (This only applies if a library manager exists. For example this rule does not apply to C/C++ libraries as no managers exist) 
The minimum requirement is an explanation of what the library does, and how to install and use it. You should publish it to a package index (see above) and provide a link!
APIs
It has to be hosted! Provide an interface like - Swagger or Scalar, where everyone can try out every of your endpoints. (Ensure your README is extra detailed!)
You should not provide a link to your API with no documenation.
AI/ML projects
You should upload a precompiled script to setup and install the necessary tools to run your project.
You should not upload it to the Hugging Face (unless its the paid plan).
Esolangs:
Provide a web-based playground 
Give detailed installation instructions and a syntax guide 
If your project is different feel free to ask in #hideout-help 
Horizontal Rule
Repository
Your repository needs 2 things:
The first is - your project code! 
Everyone that creates and submits projects to Hack Club - has to be open sourced. In most cases your code will be on the GitHub, but you're welcome to use any git provider, even self-hosted one.
Second part is - your README!
Your README represents your project, it's the first thing people see when they visit your repository so make sure it represents it well! Below, we have what a README should include and how to write a great one!
Horizontal Rule
README
There's no strict list for what your readme should have, but aim to have the following:
some images of your project
a description of your project
instructions on how to try your project out 
inspiration? Why'd you make your project?
technologies you've used - you don't need to list everything!
Remember that this is the place where you can talk about your project and say whatever you want!
As well as following what was previously mentioned in the guide! Please follow this Stardance guide for how to write a great README! 

Horizontal Rule
When To Mark A Project As Updated?
You should mark your project as updated if you shipped it to another Hack Club event or started it before hideout
Horizontal Rule
AI
Although we allow AI assisted projects but we will only approve high quality submissions that we can see you put effort into, these things are still not allowed
You may not have AI-generated assets, images, photos, etc…; (these just looks bad :/)
Your project’s front-end must not show signs of ai slop, as the design would be super ugly/unusable - try to guide your AI to design a good frontend
Your readme or any text written needs to be human-edited or entirely human

Finally remember to use #kairos and hackatime, we need both to accurately measure your time and your project hours might get deflated
Horizontal Rule
Hour Deflations:
To avoid any hour deflations please do this:
Make sure to commit to github as frequently as possible, at least every 30 minutes, if you didn’t do this your hours might get deflated
Make sure to put effort into your project, try to build a high quality project and spend time on it, low effort projects will be rejected

Still have questions?

Feel free to ask in #hideout-help 
Happy shipping!
